# AICC UI V5：审计、设计规范与验收

## 0. 基线与边界

- 基线：`origin/main` `02f8085`（PR #111–#114 已合并）。
- 构建：`macos/build-aicc-swiftui.sh`；真实 UI 离屏渲染：`scripts/smoke-test-console-visual.sh`。
- 基线 CI：`changes`、`test`、`lint`、`rust`、`swift-test`、`macos-build`、`android`、`android-visual` 均成功；`macos-dmg` 查询时仍在运行，与本轮 PR 验证无关。
- 本轮只改 SwiftUI 主框架、公共视觉、总览、AI 账号及必要弹窗。Rust、SQLite、RPC、授权、调度、轮换状态机均不改。
- 严重度：P0 = 信息错误或关键操作不可用；P1 = 明显影响日常效率/视觉验收；P2 = 一致性与维护问题。

## 1. 全局审计结论

AICC 的问题不是“卡片不够漂亮”，而是把数据库字段、机制说明、监控、操作和诊断同时平铺到首屏。V5 采用三条规则：

1. **首屏只回答决策问题**：现在是否正常、今天是否完成、下一步要做什么。
2. **正常状态静默，异常状态可行动**：不反复展示“正常/已接入/无异常”；异常必须带入口。
3. **实体、身份、设备分开**：服务账号不等于客户端登录；Qoder 服务账号不等于本机 Profile；Magpie 额度不等于账号官方额度。

## 2. 信息架构重整

### 总览

- **保留**：账号总体状态、今日任务结果、需要处理的异常、最近重要活动、成长活跃的必要摘要。
- **删除**：独立“服务账号/授权正常/今日完成/需要处理”四张卡；页面同步时间条；平台卡中的同步时间；正常状态反复说明。
- **合并**：账号与授权汇总为一条状态摘要；签到、成长、旅行、Credits 合并为“今日任务”；四平台统计改为一组列表行。
- **下沉**：成长活跃完整表格、接口机制、同步细节；异常原始技术信息只在错误详情/help 中展示。
- **重设计**：打开后 5 秒内可回答“整体如何、今天如何、要处理什么”；点击异常直接到账号或任务上下文。

### AI 账号

- **左栏保留**：名称、明确平台/版本、异常授权、当前客户端登录标记；搜索、平台筛选、添加账号。
- **左栏删除**：完整/截断 UID、邮箱（默认）、轮换计划、停留状态、恢复按钮、授权技术来源。
- **右栏首屏**：名称与平台、授权状态、当前登录、今日任务、可用额度（已有快照时）、一个主操作。
- **折叠/菜单**：授权来源列表、PAT 检测与移除、奖励、UID、路径、指纹、快照细节、删除/移除。
- **不合并实体**：WorkBuddy 国内版、WorkBuddy 国际版、Qoder 中国版、Qoder 国际版、Qoder 本机配置始终独立分组与命名。

### 额度看板（下一阶段）

- 主列表只放平台/账号、剩余量、用量进度、重置、数据时效。
- Magpie 与账号官方额度保持来源分段；不同单位、不同口径不相加。
- 数据来源、接口限制、缓存机制放详情/help；更新失败与旧快照必须可见。

### 签到任务（下一阶段）

- 统一任务视图，不再让每个任务类型创造一套卡片。
- 首屏：任务名称、账号、状态、最近结果、下一次执行、主操作。
- 自动与手动入口必须分开命名；执行历史、规则与复杂参数进入详情。

### 设置（下一阶段）

1. **常规**：外观、小组件、登录启动、项目更新。
2. **连接与设备**：Magpie、墨水屏、配对、局域网。
3. **授权与存储**：首选授权、钥匙串/JSON、显式迁移；风险确认保留。
4. **高级与诊断**：Worker 自检、轮换时区规则、TLS、指纹、日志、退出。

## 3. UI V5 设计规范

### 布局 Token

| Token | 值 | 用途 |
|---|---:|---|
| 最小窗口 | 960×640 | 所有关键操作必须可见或可滚动到 |
| 推荐窗口 | 1120×760 | 默认验收尺寸 |
| 宽窗口 | 1440×900 | 不设置窄内容最大宽度，增加留白而非拉行长文 |
| 主导航 | 208 | 固定；4 个一级页面 |
| 账号列表 | 276 | 独立滚动；详情自适应 |
| 页面水平边距 | 28 | 统一内容基线 |
| 页面上下边距 | 24 / 28 | 首段与页尾 |
| 页头高度 | 72 | 标题与全局操作 |
| 段间距 | 24 | 信息分组，不靠卡片区分 |
| 组内间距 | 12 | 标题、内容、辅助信息 |
| 行高 | 44；账号行 52 | 可点击区域至少 28pt 高 |
| 控件高度 | 30 | 主/次按钮、搜索、筛选 |
| 圆角 | 8 控件 / 12 容器 | 不使用装饰性大圆角 |
| Sheet | 小 440–480；中 560；内容超高滚动 | 底部主按钮右置，取消左置 |

### 字体

- 页标题 24 semibold；详情标题 20 semibold；状态摘要 28 semibold。
- 段标题 15 semibold；行标题 13 medium；正文 13；辅助文字 12；仅极次要信息 11。
- 数字使用 `monospacedDigit`；UID/路径才使用等宽字体。
- 长名称最多两行；列表一行尾省略；UID 中间省略；关键操作禁止缩成不可读文字。

### 配色与状态

- 大面积使用动态中性色；浅色/深色分别定义，不反转固定色值。
- 主操作/选中使用系统蓝语义色；品牌图形可保留少量青绿色，但不给整页染色。
- 成功：绿；警告：橙；错误：红；未知：灰。正常状态优先文字/小点，错误才使用浅色底。
- 不用颜色作为唯一状态线索；同时有文字或 SF Symbol。

### 组件

- **页面摘要**：无卡片的大标题+一句辅助信息，可带 2–4 个关键数字。
- **平面分组**：段标题+内容；用间距与分隔线建立层级。
- **列表容器**：一张容器承载多行，禁止每行再嵌套卡片。
- **主按钮**：每个视图一个；次按钮用于并列低频动作；更多菜单收纳低频/危险项。
- **徽章**：只用于当前登录、异常、临时状态；不为所有正常账号加彩色胶囊。
- **空状态**：一句原因+一个下一步；加载使用小型 ProgressView，不伪造 0。
- **错误**：先说“什么失败”，再给“重试/重新登录/查看详情”；原始错误只保留必要一行。

### 自适应验收

- 960×640、1120×760、1440×900 × 浅色/深色。
- 水平空间不足时用 `ViewThatFits`/网格换行，不固定超宽表格。
- 页面与左右列表分别可滚动；不允许内容撑出窗口。
- 按钮不被截断、数字不重叠、基线一致、长名称不挤压状态、关键操作有最小点击区域。

### 直接删除或改为短标签

| 原文/类型 | V5 |
|---|---|
| 客户端当前登录的就是这个账号 | 当前登录 |
| 账号列表、授权与详情 / 账号、任务与异常 | 删除副标题 |
| 认证有效（列表中重复） | 正常；正常行也可不显示状态 |
| 还没有登记任何授权来源，请重新登录一次 | 需要登录 |
| 当前服务端授权状态无法确认 | 授权待确认 |
| 未提供经过验证的官方接口 | 暂不支持 |
| 最近一次获取额度数据失败 | 更新失败 |
| 账号没有可用的认证来源 | 需要登录 |
| 这一轮已经结束，并且已成功恢复最初的账号 | 已恢复 |
| AICC 后台请求用……只影响……不影响…… | 默认删除；授权详情的 help 中按需保留 |
| 可用能力：已接入 / 官方额度：账号额度看板 | 删除；直接提供可用操作 |
| 令牌归 Magpie 刷新，AICC 只借用…… | 短标签“Magpie 关联”；说明进 help |
| 服务端没有余额接口 / 该版本未验证，不会发请求 | 暂不支持；help 说明范围 |
| Worker / RPC / Snapshot / auth_epoch / cdhash | 不出现在普通 UI；仅诊断或开发文档 |
| 最近同步时间、统计日 | 首屏删除；数据时效异常时保留 |

### 移入 help、详情或高级设置

- 授权来源刷新责任、明文 JSON 布局、PAT 权限边界。
- 签到与成长活跃的统计口径；Magpie 与官方额度的来源差异。
- 本机 Profile 的目录、Token 指纹、快照完整性、Bundle ID。
- 轮换时区、错过开始不补跑、恢复余量、调度执行者。

### 必须在异常或确认流程保留

- 切换/轮换会关闭并重启客户端，可能中断正在进行的对话。
- Magpie 临时登录的到期时间、恢复动作、失败自动恢复边界。
- 当前登录已变化时继续恢复会覆盖现有登录态。
- 明文凭据风险与显式同意；关闭 JSON 不自动迁回钥匙串。
- 永久删除、移除账号/PAT、撤销设备、重置 TLS 身份的影响范围。
- 数据为旧快照、查询失败、授权待确认；不得把未知写成 0 或正常。

## 8. 真实应用路径闭环（#115 复审第二轮）

### P0：冷启动读取轮换状态

- `ConsoleStore.loadIfNeeded()` 首次进入窗口时并行调用只读的 `refreshWorkbuddyRotation(silent: false)`；不签发、不切换、不恢复。
- 新增 `wbRotationLoading`：加载中、读取失败、已确认无异常是三种状态。
- 新增可测试状态机 `ConsoleRotationAttentionState` / `ConsoleOverviewAttention`：
  - 只有已读到状态且 `attentionRun == nil` 才会出现“一切正常”；
  - 加载中 → 首屏「状态待确认」；
  - 读取失败（即使手里有旧状态）→ 不计为正常，待处理出现「轮换状态无法确认」，点击打开轮换面板；
  - `attentionRun` 存在 → 计入摘要与待处理（「WorkBuddy 轮换未恢复」）。
- 恢复成功后由 `restoreWorkbuddyRotationOrigin` 刷新轮换与客户端状态，警示自动消失。
- 总览刷新按钮也会重读轮换状态。
- 模型已移入 `Sources/Models/` 并加入 `AICCCore` 测试目标。

### P1：首次挂载消费导航请求

- `ConsoleNavigation` 增加 `requestRotationSheet()` 与一次性 `consumeRotationSheetRequest()`；
- 账号页在 `.onAppear` 与 `.onChange` 都消费：请求先于视图创建（首次挂载值为 true）也能打开面板；

- `openRotationSheet` 改为 `private(set)`，只能通过请求/消费 API 操作。
