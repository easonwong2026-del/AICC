### 1.2 现在页面展示了什么

页面级：

1. 页头「签到任务」+ 全局刷新 + 设置（`MainConsoleView`）。
2. 「运行规则」整行按钮 + 右端「刷新状态」：一行只放两个按钮，中间大片空白。
3. 「今日摘要」卡：日期、今日完成 / 待完成 / 自动任务 / 最近失败 四个数字，
   外加最多 3 条失败明细（`签到 设计外包 令牌已过期…`、`成长 accept 批量账号 6 任务已下架`）。
4. 平台选择：`WorkBuddy CN ✓` / `Qoder CN` 两个自绘 chip，右侧一句说明
   「WorkBuddy AI 与 Qoder International 没有签到类任务，因此不在这里」。
5. 任务类型选择：`每日签到` / `成长中心` / `Buddy 旅行` 三个胶囊；Qoder 下渲染一个
   **选中的、但点击无任何反应**的 `每日 Credits` 胶囊（`action: {}`）。

每日签到：

6. 分区标题 + `1 个需处理` + `3 个未签到` 徽章 + `1 个需处理` 徽章 + 刷新图标。
7. 摘要行：`今日 8/12 已签到` `自动开启 6 个账号` `今日 AICC 签到 +100` `本地记录`。
8. 卡片表格：账号（昵称 + 两行说明）、今日状态徽章、奖励、自动开关、`立即签到`。
9. 页脚：`刷新全部状态`、`立即签到未完成账号`、`最近检查：…`、`下次自动检查：…`、
   操作提示、错误、`计划 09:00（UTC+8（北京时间））· 自动执行只在 AICC 运行时发生`。
   960×640 与 1120×760 下页脚都在首屏之外（见 1.6）。

成长中心：

10. 分区标题 + 长 detail（`2 个账号 · 1 项待领奖 · 1 项可接受 · 11:56 扫描 · 只读`）+
    `1 项待领奖` 徽章 + `扫描`。
11. 卡片内自动管理条：开关、间隔、下次检查、`立即检查`、最近结果、提示、
    「开启后只做接单与领奖，不代替你完成任何任务。」
12. 账号折叠行：箭头、昵称、授权来源徽章、档案摘要、状态徽章、任务计数串、
    `已领 +N`、旅行状态。展开后是每个任务的：图标、标题、条件（最多两行）、
    上次执行、进度、奖励、状态徽章、类型徽章（自动/真实操作/人工/待识别）。
13. 页脚：「自动管理已开启：只接单与领奖…」/「当前只读…」+ 接口前缀 help。

Buddy 旅行：

14. 分区标题 + 间隔 detail + `自动 N 个账号` 徽章 + 刷新图标。
15. 卡片行：昵称、`Magpie` 徽章、结果小字、阶段徽章、目的地、自动开关、
    `领取`、`派出`、单账号刷新；行下橙色警告。
16. 页脚：结果提示 + 「自动旅行由 AICC 的账号助手进程执行：只在 AICC.app 运行时工作，
    上次检查 11:20。App 退出后不会在后台残留进程。」

Qoder 每日 Credits：

17. 分区标题 + 账号数 + 刷新按钮。
18. 每个账号**一张卡**：昵称、版本、状态胶囊（`未支持`/`自动已开`/`自动关闭`）、
    `检查今日`、`立即领取`、`自动领取` 开关、最近一次记录、最多 5 条领取历史。
19. 提示行。

### 1.3 用户日常必须看到的状态

- 每个账号今天签没签、拿了多少（`服务端确认` 语义不能丢）。
- 哪些账号今天还没签、哪个失败/需要登录。
- 自动签到开关、下一次自动检查时间（用户要判断"要不要现在手动点"）。
- 成长：每个账号待领奖数量、任务完成进度、是否已授权、自动管理是否开启。
- 旅行：在哪个城市、处于派出/旅行中/已到达/今日已完成、能领多少。
- Credits：今天可领/已领/无活动/暂不支持、最近一次结果。
- 加载中、读取失败、未知（不能显示成 0 或成功）。

### 1.8 十个必答问题

1. **展示什么**：见 1.2；本质是把「汇总数字 + 平台/任务选择 + 四套互不相同的分区布局」叠在一页。
2. **日常必须看到**：见 1.3。
3. **重复统计**：见 1.4；同一事实最多出现 4 次（今日完成最严重）。
4. **开发说明**：见 1.5；共 9 类，全部属于机制/接口/调度解释。
5. **高频操作**：批量签到、单账号签到、旅行领取、成长扫描/立即检查、Credits 检查+领取、自动开关。
6. **风险操作**：O4/O5/O8/O9/O12/O13/O18/O19；现状**都没有确认框**（服务端幂等 + 先查后写），
   本轮保持这一行为，不新增也不删除确认。
7. **应折叠**：领取历史（Credits 5 条）、任务条件与类型理由、接口前缀、宿主机说明、运行规则。
8. **独立自动规则**：签到=每账号开关、每天 09:00 后一次；成长=**全局单开关**、24h、
   只接单+领奖；旅行=每账号开关、派出 30 分钟/领取 10 分钟节奏、仅 App 运行时；Credits=每账号开关、按服务端活动窗口。
9. **仅手动**：所有手动按钮都不受自动开关限制；手动 tick 在自动关闭时是只读；旅行领取/派出、
   Credits 领取、签到提交都只能由按钮触发。
10. **不合理之处**：见 1.6。

## 3. 新页面结构

```
签到任务
├─ 工具栏   [WorkBuddy CN | Qoder CN]  [每日签到 | 成长中心 | Buddy 旅行]   ?   检查状态/扫描/重读快照/刷新
├─ 任务摘要  今日完成 3   待处理 2   执行异常 3                 当前任务：每日签到
└─ 当前任务（一次只渲染一个）
   ├─ 每日签到   账号 | 今日 | 奖励 | 最近执行 | 自动签到 | 操作   + 标题行「签到未完成账号（N）」
   ├─ 成长中心   账号 | 任务 | 最近执行 | 状态 | ⌄                 + 自动管理行（开关 + 立即检查）
   ├─ Buddy 旅行 账号 | 当前状态 | 奖励 | 自动 | 操作
   └─ 每日 Credits 账号 | 今日 | 奖励 | 自动领取 | 最近执行 | 操作
```

- **摘要与表格同源**：三个数字都由当前任务域的展示行派生，切换任务时一起变，不会出现「摘要 11 / 表格 8」。
- **没有数据就不摆数字**：无账号、未扫描、加载中都不显示 `0 0 0`；加载中显示 `—`。
- **正常弱化、异常明确**：正常成长账号只有一个 5pt 绿点；异常用「短标签 + 语义色」，颜色从不是唯一线索。
- **每屏一个主按钮**：签到是标题行的「签到未完成账号（N）」（960×640 也在首屏），成长是自动开启时的「立即检查」，
  旅行/Credits 是可领取行上的「领取」。
- **表格语言与额度看板一致**：`ConsoleListSurface` + `micro` 表头 + 行分隔线，不在行内再套卡片。

## 4. 状态词汇（不展示 Rust 字段名）

| 展示 | 含义 | 语气 |
|---|---|---|
| 已完成 | 服务端确认今天已签到 | 绿点 + 中性文字 |
| 待处理 | 服务端确认未完成，等人处理 | 橙点 + 橙字 |
| 已接受 / 进行中 | 成长任务已被接受 / 进行中 | 灰点 + 中性文字 |
| 执行中 | AICC 正在提交，禁止重复点击 | 灰点 + 中性文字 |
| 可领取 | 有奖励可领（旅行到达 / Credits / 成长待领奖） | 橙点 + 橙字 |
| 领取成功 | 服务端确认领取成功 | 绿点 + 中性文字 |
| 待确认 | 请求已发但服务端未确认 | 橙点 + 橙字 |
| 需要登录 | 授权失效或缺失 | 红点 + 红字 |
| 暂不支持 | 该版本没有已证实接口 | 灰点 + 灰字 |
| 执行失败 | 服务端拒绝 / 网络失败 | 红点 + 红字 |
| 已锁定 | 成长任务锁定 | 灰点 + 灰字 |
| 待查询 | 还没查过，不能当成 0/成功 | 灰点 + 灰字 |
| 暂无活动 | Credits 窗口内没有可领活动 | 灰点 + 灰字 |
| 部分失败 | 成长扫描部分接口失败 | 橙点 + 橙字 |
| （无文字） | 成长账号正常 | 仅绿点 |

「待确认」计入页面的「执行异常」：结果没定就不能当正常。`unknown` 永远不会映射成「已完成 / 领取成功」。

## 6. 业务边界核对

1. **签到调度**：未改 worker / 09:00 计划 / 每账号开关语义；页面加载与「检查状态」只调用 `checkinStatus(cached:)`。
2. **签到判定**：`claimed / already` 仍是唯一「已完成」；`unknown` → 「待确认」；`disabled` → 「待查询」。
   授权失效（含 `failed + errorKind=unauthorized`）与不支持的平台**不再给出可点的写按钮**，help 指向「AI 账号」。
3. **成长**：未改扫描接口、去重、领取、回查；自动管理仍是全局单开关；手动 tick 仍受总开关约束（关闭时只读）。
   本轮只把自动管理条从「扫描后才有」改成「一直可见」。
4. **旅行**：未改状态机与派出/领取条件；页面加载只读 `travel.summary`（10 秒轮询本地快照），
   行内刷新仍是 `travel.refresh`（只读），派出/领取仍只在用户点击时发生。
5. **奖励链路**：抽奖/兑换/补签仍在账号详情，`ConsoleRewardsSection.swift` **零 diff**（预览→确认→执行→回查未动）。
6. **Credits**：「立即领取」仍要求本次会话确认 `claimable`（且 `claimed != true`）；
   未领取/已领取/失败/未知分开；每日奖励不进入任何余额列（本页没有余额列）。
7. **平台边界**：WorkBuddy CN 才有签到/成长/旅行；Qoder CN 才有 Credits；
   Qoder International 的自动领取开关仍禁用；不支持的账号没有可执行的写按钮。
8. **后端零改动**：`git diff --stat origin/main -- account-worker server.py collectors tests macos/Android VERSION` 为空。
