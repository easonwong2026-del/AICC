# Provider UI 规范：额度字体与信息层级

## 原则

> 额度数字优先，状态其次，说明最后。

所有卡片共享同一套设计 Token（`DashboardTypography`），禁止在卡片里散落魔法数字。

## 字号 Token

| Token | 值 | 用途 |
| --- | --- | --- |
| `primaryMetricLarge` | 36 | 普通卡片主数值 |
| `primaryMetricCompact` | 30 | 紧凑卡片主数值 |
| `secondaryMetric` | 16 | 第二个 Primary / 次级数值 |
| `metricLabel` | 12 | 指标标签 |
| `unit` | 13 | 单位 |
| `status` | 11 | 状态 |
| `timestamp` | 10 | 更新时间 |

建议范围（供参考，Token 为准）：

- 紧凑卡片主数值 26–32pt
- 普通卡片主数值 32–40pt
- Codex 百分比核心数字 30–38pt
- WorkBuddy 积分 30–38pt
- DeepSeek 余额 28–36pt
- 单位 11–14pt、标签 11–13pt、状态与更新时间 10–12pt

## 数字与单位分层

不要把 `5,343.37 积分`、`92% Weekly`、`¥128.50 余额` 放在同一字号：

```text
5,343.37    积分
92          %
128.50      CNY
```

数字明显大于单位，单位基线对齐。

## 长数字规则

必须正确显示：`9`、`99`、`999`、`5,343.37`、`12,500`、`999,999.99`、`1,234,567`。

- 默认千位分隔；
- 最多保留必要小数位（默认 ≤2，长数字先降为 0 位小数）；
- 不使用科学计数法、不直接截断；
- 不因数值变长把主字体缩到不可读；必要时减少小数位而不是无限缩小字号；
- 极长数字只在 `format: "compact"` 时使用 `1.23M`；
- 金额与积分不得混淆单位。

## 自适应算法

字号根据卡片宽度、数字字符数、是否含小数、是否含货币符号、是否紧凑模式统一计算：

```swift
DashboardTypography.primaryFontSize(number: "5,343.37", compact: true)
```

- ≤4 位数字：基准字号（36 / 30）
- 5–6 位：基准 −2
- 7–9 位：基准 −4
- ≥10 位：普通 30 / 紧凑 24，配合小数位归零

## 卡片布局规则

动态 `ProviderCard`：

1. 第一个 `primary=true` Metric：大号主数值；
2. 第二个 Primary Metric：中等字号（`secondaryMetric`）；
3. 最多显示 2–3 个 Secondary Metric；
4. 其余数据进入详情或诊断页；
5. 不允许所有 Metric 平铺成同样大小的小字；
6. 卡片高度尽量稳定，新 Provider 不得无限撑高菜单栏。

## 状态与错误展示

- WorkBuddy：主视觉是**真实剩余积分**；优先级为 剩余积分 → 今日使用 → Connected/Cached/Unavailable → 更新时间；
- 有最近成功缓存：显示大号缓存积分 + 明确 `Cached` + 缓存年龄；
- 无有效积分：主区域显示“暂不可用”，**不显示 0**、不显示旧手工积分；
- DeepSeek：主视觉是当前余额，今日使用为次级，不同币种必须明确显示；
- Codex：Weekly 为第一视觉层级（数字最大、进度条加粗），5 Hour 为次级数据，重置时间小号辅助文字。

## 可读性验收

正常 Mac Retina 屏幕、不放大系统显示时：

- 额度数字一眼可读；
- 主数字与辅助文字字号差异明显；
- 无明显裁切、拥挤换行；
- 中英文切换布局不破坏；
- 浅色/深色均可读；
- VoiceOver 能读出标签、数字和单位。
