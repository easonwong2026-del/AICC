# AICC v2.13.0 / macOS Build 25

## 中文

### 成长中心 · 奖励

- **三档连登奖励可查可领。** 账号详情新增「奖励」区块：7 / 14 / 28 天档位状态、抽奖次数、
  补签卡余额、可补签日期与最近 5 条本地账本记录。数据来自只读的 `growth.rewards.status`。
- **三个写动作接线并加护栏。** 抽奖 / 兑换 / 补签统一走
  「实时余额预览 → 二次确认 → 记本地账本 → 只发一次请求 → 回查服务端」。
  结果未知时只能「回查」，不会自动重发；账本读不到时显示"无法确认"，不会显示 0 条。

### 成长中心 · 活跃

- **四账号成长活跃看板。** 总览页第二层：今日活跃、今日签到、连登天数、下一档还差几天、
  最近 7 天活跃天数与上次活跃日期。每账号 2 个成长 GET，只有本地拿不出成功签到记录时
  才多发 1 次只读语义 POST（签到状态接口）。
- **签到与活跃分开算。** 签到结论分五种：已签（本地）/ 已签（服务端）/ 未签到 /
  签到失败 / 未确认。本地成功只认存储层的 `claimed` / `already`；本地已确认时不发任何查询。
- **七种诊断各带动作：** `active`、`checkin_only`、`checkin_unverified`、`inactive`、
  `stale_stats`、`unknown`、`needs_auth`。未知和"疑似延迟"不催人，授权问题提示重新授权，
  「打开客户端」只出现在需要真实使用的两种状态上。
- **不伪造活跃。** 不模拟客户端、不批量发对话、不做"一键活跃"。需要活跃时只提醒你去官方
  客户端真实使用一次，回来点刷新回查。

### 可靠性

- 活跃判定覆盖 45 组组合矩阵、跨日、离线、401/网络失败、多账号归属、连登只取服务端、
  连续刷新无写操作、调试探针只在开发构建注册。
- 签到状态查询只在 404 时换路径；401 / 403 / 429 / 5xx / 超时都不重试、不刷新令牌、
  不发签到写请求。
- CI 按路径过滤 + 并发取消，PR 全量检查墙钟从约 15 分钟降到约 7 分钟。

## English

### Growth center · rewards

- **Streak rewards are visible and claimable.** The account detail page now shows the 7 / 14 / 28-day
  tiers, lottery chances, makeup cards, dates that can be made up and the last five ledger entries,
  all from the read-only `growth.rewards.status`.
- **Three write actions are wired, each behind a guard rail.** Draw / redeem / makeup go through
  live balance preview → explicit confirmation → local ledger → exactly one request → server recheck.
  Unknown outcomes can only be rechecked, never re-sent; an unreadable ledger reports "unknown", not zero.

### Growth center · activity

- **Four-account activity board** on the overview page: today's activity, today's check-in, streak
  length, days left to the next tier, active days in the last week and the last active date.
  Two growth GETs per account, plus one read-only POST (check-in state) only when the local record
  cannot answer.
- **Check-in and activity are separate signals.** Check-in reports confirmed (local) / confirmed
  (server) / not checked in / failed / unconfirmed. Local success is judged only by the stored
  `claimed` / `already` values, and a confirmed local record sends no extra request.
- **Seven diagnoses, each with its own action:** `active`, `checkin_only`, `checkin_unverified`,
  `inactive`, `stale_stats`, `unknown`, `needs_auth`. Unknown and possibly-delayed states never nag;
  auth problems ask for re-authorization; the "open client" button appears only for the two states
  that need real usage.
- **No activity is ever faked.** No client emulation, no batch conversations, no one-click activity.
  When a real task is needed, AICC only points at the official client and rechecks afterwards.

### Reliability

- Activity coverage spans a 45-case diagnosis matrix, day rollover, offline, 401/network failures,
  per-account attribution, server-only streak values, no-write-on-refresh and a guard that keeps
  debug probes out of release builds.
- The check-in state query only falls back on 404; 401/403/429/5xx/timeouts never retry, never
  refresh a token and never submit a check-in.
- CI path filters plus concurrency cancellation cut a full PR run from about 15 minutes to about 7.

## 安装 / Installation

- macOS：下载 `AICC-2.13.0.dmg`，核对 SHA256；退出旧版 AICC 后把应用拖入 `/Applications` 替换，再启动。
- macOS: Download the DMG, verify its SHA256, quit the old AICC, replace the app in `/Applications`,
  then launch it.
- **签名身份从 ad-hoc 换成本机固定证书 `AICC Local Code Signing`**（仍是自签名，未经 Apple 公证）。
  首次启动可能弹一次钥匙串授权，点「始终允许」即可；之后的同证书构建不会再问。
- **The signing identity changed from ad-hoc to a fixed local certificate** (`AICC Local Code Signing`;
  still self-signed, not notarized). The first launch may ask for keychain access once — choose
  "Always Allow"; later builds with the same certificate will not ask again.
- 桌面上已有的小组件如果变空白，移除后重新添加一次即可（小组件配置本身不受影响）。
- If an existing desktop widget goes blank, remove and re-add it once; its settings are preserved.
- 需要 macOS 14+ 与 Apple Silicon。DMG 内置完整 Python 3.14 运行时，不再依赖系统 Python。
- Requires macOS 14+ and Apple Silicon. The DMG bundles the full Python 3.14 runtime; no system
  Python is needed.
