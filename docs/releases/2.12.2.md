# AICC v2.12.2 / macOS Build 24

## 中文

- **修复桌面小组件整块纯黑**：这是 2.12.1 的一个真实缺陷。桥接进程把运行数据写进了 App 包内部的
  `Contents/Resources/Server/data/`，而 ad-hoc 签名是逐文件哈希——多出两个文件（`host_id`、
  `magpie_last_success.json`）后 `codesign --verify --deep --strict` 立刻变成
  `a sealed resource is missing or invalid`。seal 一坏，macOS 就不再登记这个 Widget 扩展
  （`chronod` 的注册表里查不到它），桌面上只剩系统画的空壳黑框，一个字都没有。
- **根因修复**：`EINK_DATA_DIR` 未设置时，`collectors/magpie.py` 会退回到「脚本同级的 `data/`」，
  在安装态下这个位置就在 App 包里面。现在只要解析出的目录落在任意 `.app` 内部，就强制改道
  `~/Library/Application Support/AICC-Dashboard/data` 并在 stderr 记一行。源码目录照旧用 `./data`，
  显式指定 `EINK_DATA_DIR` 依然优先，三种情形都不变。
- **升级后自动自愈**：主机 App 每次构建号变化后首次启动会做三件事——递归清掉自身 bundle 的
  `com.apple.quarantine`（从网上下载的 DMG 会给每个嵌套 bundle 都打上隔离，扩展是被单独评估的）、
  `pluginkit -a` 重新注册 `AICCWidget.appex`、重启 `chronod` 让它丢弃旧描述符。每步都会写一行
  `~/Library/Logs/AICC-Dashboard/widget-health.log`（含返回码），出问题时不必再猜。
  只动自己的扩展和用户级 `chronod`，不碰其他进程。
- **发版自检**：`validate-widget-bundle.sh` 新增两条断言——bundle 内不得存在 `Server/data`，
  且 `codesign --verify --deep --strict` 必须通过。上面那个缺陷本可以在发布前被这条挡住。
  `smoke-test-bundled-server.sh` 增加用例：在 `.app` 内部、不带 `EINK_DATA_DIR` 启动服务器，
  断言它没有写进 bundle、并确实改道到了 `~/Library/Application Support`。
- **修复升级后 App 卡死**：桥接密钥原先存在登录钥匙串的 `kSecClassGenericPassword` 条目里，条目 ACL 绑定
  签名身份；ad-hoc 每次重建 cdhash 都变，`SecItemCopyMatching` 于是去等一个访问授权对话框——而
  `LSUIElement` 菜单栏 App 没有窗口能显示它。结果是 App 永久卡在启动阶段，桥接、小组件、设置全部不工作，
  只能手工删条目。密钥改为存在 `~/Library/Application Support/AICC-Dashboard/bridge-token`（0600），
  旧钥匙串条目只在迁移时读一次且有 2 秒硬超时，之后不再触碰。
- **测试**：`tests/test_magpie.py` 新增 `DataRootTests`（5 项），覆盖源码目录、显式指定、bundle 无变量改道、
  变量指向 bundle 内部也改道、以及 `.app` 判定只认嵌套路径；`WidgetInstallationTests`（6 项）覆盖
  App Translocation 路径判定。

## English

- **Desktop widgets render as a solid black tile** — a real 2.12.1 defect. The bridge wrote its runtime data into
  `Contents/Resources/Server/data/` inside the App bundle, and an ad-hoc signature hashes every file: two added
  files (`host_id`, `magpie_last_success.json`) turned `codesign --verify --deep --strict` into
  `a sealed resource is missing or invalid`. A broken seal means macOS no longer registers the Widget extension
  (it is absent from chronod's registry), so Desktop draws the system's empty shell — a black rounded rectangle
  with no text on it.
- **Root cause fixed**: when `EINK_DATA_DIR` was unset, `collectors/magpie.py` fell back to `data/` beside the
  script, which inside an installed App is the bundle itself. Any resolved directory that lands inside a `.app`
  is now redirected to `~/Library/Application Support/AICC-Dashboard/data`, with one line on stderr. A source
  checkout still uses `./data`, and an explicit `EINK_DATA_DIR` still wins.
- **Self-healing after an upgrade**: on the first launch of a new build the host App recursively clears
  `com.apple.quarantine` from its own bundle (a downloaded DMG marks every nested bundle, and extensions are
  assessed on their own), re-registers `AICCWidget.appex` with `pluginkit -a`, and restarts `chronod` so it drops
  the stale descriptors. Each step logs a line with its exit status to
  `~/Library/Logs/AICC-Dashboard/widget-health.log`, so a failure is diagnosable without a debugger.
  It touches only its own extension and the user's `chronod`.
- **Ship-time guard**: `validate-widget-bundle.sh` now asserts that no `Server/data` exists inside the bundle and
  that `codesign --verify --deep --strict` passes — this would have caught the shipped defect before release.
  `smoke-test-bundled-server.sh` starts the server inside a `.app` without `EINK_DATA_DIR` and asserts it neither
  writes into the bundle nor fails to redirect.
- **Tests**: `tests/test_magpie.py` gains `DataRootTests` (5 cases) covering the source checkout, an explicit
  directory, a bundle without the variable, a variable pointing inside a bundle, and nested-only `.app` detection.
- **The App no longer hangs after an upgrade.** The bridge secret lived in a login-keychain
  `kSecClassGenericPassword` item whose ACL is bound to the signing identity. An ad-hoc rebuild changes cdhash, so
  `SecItemCopyMatching` waits for an access-authorization dialog — and an `LSUIElement` menu-bar App has no window
  to show it. The App then parks in launch forever: bridge, widgets and settings all dead until the item is deleted
  by hand. The secret now lives in `~/Library/Application Support/AICC-Dashboard/bridge-token` (0600); the old
  keychain item is read at most once during migration, under a two-second deadline, and never again.
- **`WidgetInstallationTests`** (6 cases) cover the App Translocation path rules the repair depends on.

## 安装 / Installation

- macOS：下载 `AICC-2.12.2.dmg`，核对 SHA256；退出 AICC 后将应用拖入 `/Applications` 替换旧版，再启动 AICC。
  本轮**不需要**手动敲任何命令：首次启动会自己修好扩展注册。桌面上已有的小组件建议移除后重新添加一次
  （ad-hoc 签名每次构建 cdhash 都变，系统会丢掉旧实例；额度小组件的配置不受影响）。
- macOS: Download the DMG, verify its SHA256, quit AICC, replace the app in `/Applications`, then launch it.
  **No terminal commands needed this round** — the first launch repairs the extension registration itself.
  Re-add the existing desktop widgets once; an ad-hoc signature changes cdhash on every build and the system
  drops old instances. The quota widget's settings survive.
- 沿用 ad-hoc 签名，未经 Apple 公证；需要 macOS 14+、Apple Silicon 和 Python 3.10+。DMG 内置完整服务器源码，
  不含 Python 解释器。首次打开若被 Gatekeeper 拦，右键 → 打开。
- Uses ad-hoc signing without Apple notarization. Requires macOS 14+, Apple Silicon and Python 3.10+; the server
  source is bundled, Python itself is not. If Gatekeeper blocks the first launch, right-click → Open.
- 墨水屏 APK 本轮无改动，继续用 `AICC-Poke4S-1.2.7.apk`（`versionCode 13`）。
- The e-ink APK is unchanged; keep using `AICC-Poke4S-1.2.7.apk` (`versionCode 13`).
