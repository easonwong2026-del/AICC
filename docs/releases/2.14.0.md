# AICC v2.14.0 / macOS Build 26

UI V5 的正式版本。界面全部重做，业务语义、存储与 RPC 行为保持不变。

## 中文

### 界面 V5（#115–#120）

- **统一设计系统（#115）。** 一套颜色、字号、间距与组件（页面骨架、表格、状态徽章、空/错/载入态）
  覆盖全部页面；侧边栏四个页面 + 设置中心，960×640 到 1440×900 都有浅色与深色样本。
- **总览与 AI 账号（#115）。** 总览按平台给出账号数与授权状态；AI 账号页按
  WorkBuddy 国内 / WorkBuddy 国际 / Qoder CN / Qoder Global 分组，详情页把授权来源
  （Magpie 导入 / 自有授权）、令牌有效期、签到与旅行开关、诊断入口放在同一屏。
- **额度看板（#116）。** Magpie 与账号助手两个来源、按平台筛选、7 / 30 天用量窗口。
  `0` 是数值、未知不是 `0`：缓存、旧快照、读取失败、未证实接口各自有独立状态，
  不把失败画成 0。重置时间保留原文进 help。
- **任务中心（#117）。** 今日任务按平台分成 WorkBuddy（每日签到 / 成长中心 / Buddy 旅行）
  与 Qoder Credits；摘要只由展示行派生，与列表永远同源。
- **设置中心（#118）。** 四类分组重排，重复打开不再堆窗口；桥接、端口、TLS 证书指纹、
  设备配对、凭据存储与迁移、助手诊断都在各自分类下。
- **自动计划中心与轮换配置（#119）。** 五类自动化集中显示；轮换三步配置（账号顺序、
  时间窗口与时区、停留时间）、服务端预演、仅保存 / 保存并开启、停止与恢复最初账号、
  `recovery_required` 单独提示。

### 交互收口（#120、#121）

- **刷新只有一个入口。** 额度页、旅行、Credits 的页内「刷新」与页头图标调用完全相同，
  已删除；页头图标按页面说明「重新采集」还是「重读本地」。7 / 30 天只重算窗口，不重新采集。
- **签到行动作按状态给。** 已完成 / 待确认 →「复查」（只读 `checkin.status`，永不发 `checkin.run`）；
  待签到 →「立即签到」；网络失败 →「重试」；授权失效 →「去登录」（纯导航，定位到该账号）；
  不支持 / 执行中 → 不给第二个入口。
- **复查失败不再伪装成功。** 单账号复查失败保留上一份已确认状态，原因单独以错误样式展示；
  成功或整队刷新成功后清除。
- **菜单栏退出（#121）。** 常驻菜单栏图标：打开主控制台 / 设置… / 退出 AICC。
  之前唯一的退出入口在「设置 → 高级与诊断」，窗口关掉后找不到。
- **Credits 自动领取。** 失去资格但已开启的账号仍可关闭；提交后回读服务端真实状态，
  未确认就不说成功。

### 安装与升级

- **`/Applications` 与 `~/Applications` 都受支持。** 之前记录的「本机 `/Applications`
  启动卡在 `_dyld_start`」经复测确认**与目录无关**：根因是未公证应用带
  `com.apple.quarantine` 首次启动被 Gatekeeper 挂在 dyld 之前等确认，
  而提示框属于 `CoreServicesUIAgent`、只有「完成 / 移到废纸篓」，没有 Dock 图标的 AICC
  看起来就像「点开没反应」。完整对照实验见 `docs/INSTALL_PATH_ROOT_CAUSE.md`。
- **DMG 内附 `安装说明.txt`。** 首次被拦住时怎么放行（优先 Apple 官方的
  「系统设置 → 隐私与安全性 → 仍要打开」）、怎么退出、怎么回滚都写在镜像里。
  清除隔离属性的命令只在说明里标为开发排障手段，不作为普通用户的安装步骤。
- **小组件自愈认「身份」而不是「路径」。** 以前只按 `/Applications` →
  `~/Applications` 的顺序找安装副本；如果两个位置各有一份、版本不同，
  修复可能打到**旧的那份**。现在比较运行副本与候选副本的 Bundle ID + 主可执行文件
  cdhash，只修同一个构建；都匹配不上就什么都不做，并在日志里写清看了哪些路径、
  每份是什么版本。转位启动因此也能在 `~/Applications` 正常自愈。
- **修复失败会重试。** 清隔离或 `pluginkit -a` 失败不再记成「已修复」：
  不写完成标记，下次启动重来。完成标记由「版本 + Build + cdhash」组成，
  同版本重新构建（cdhash 变了）也会重新注册，不会因为版本号没变而跳过。

### 数据库

- 迁移版本 26 → 29，**只新增**三张轮换表（`workbuddy_rotation_plan`、
  `workbuddy_rotation_run`、`workbuddy_rotation_step`），没有删除或改写任何既有表。
  `accounts` / `qoder_accounts` 的建表语句与 2.13.0 完全一致。
- 回滚：旧版 `aicc-account-worker` 读 v29 数据库实测正常（`accounts.list` 返回全部账号）；
  但**只替换 `.app` 不还原数据库不是受支持的回滚方式**。正确顺序是：先退出 AICC 并确认
  没有残留的 worker / 内置 Python，再用一致性备份（`sqlite3 .backup`）还原数据库、
  同时清掉旧库遗留的 `-wal` / `-shm`；在数据库仍被写入时覆盖文件会得到损坏的库。
  DMG 里的 `安装说明.txt` 给了可直接照抄的命令。

## English

### UI V5 (#115–#120)

- **One design system (#115)** across every page: colours, type scale, spacing and the shared
  page scaffold / table / badge / empty-error-loading states, with light and dark renders from
  960×640 up to 1440×900.
- **Overview and AI accounts (#115).** Per-platform account counts and authorization state;
  the accounts page groups WorkBuddy CN / WorkBuddy International / Qoder CN / Qoder Global and
  puts authorization source (Magpie import vs own login), token expiry, check-in and travel
  toggles and the diagnostics entry on one screen.
- **Quota dashboard (#116).** Two sources (Magpie, account worker), per-platform filter and a
  7 / 30-day usage window. `0` is a value and unknown is not `0`: cached, stale, failed and
  unverified states are separate, and a failure is never drawn as zero.
- **Task centre (#117).** Today's tasks split into WorkBuddy (daily check-in / growth / Buddy
  travel) and Qoder Credits, with the headline derived from the displayed rows only.
- **Settings centre (#118).** Four categories, one window; bridge, port, TLS fingerprint, device
  pairing, credential storage and migration, worker diagnostics each in their own section.
- **Automation centre and rotation setup (#119).** All five automations in one place, a three-step
  rotation setup (account order, time window and timezone, dwell time), server-side preview,
  save-only / save-and-enable, stop and restore, and a dedicated `recovery_required` warning.

### Interaction polish (#120, #121)

- **One refresh entry per page.** In-page refresh buttons for quota, travel and credits called
  exactly the same store methods as the header icon, so they are gone; the header hint says
  whether it re-collects or re-reads locally. The 7 / 30-day switch only recomputes the window.
- **Check-in actions follow state.** Done / unconfirmed → read-only «复查» (`checkin.status`,
  never `checkin.run`); pending → «立即签到»; network failure → «重试»; expired auth → «去登录»
  (navigation only, landing on that exact account); unsupported or running → no second entry.
- **A failed recheck no longer looks like success.** The row keeps its last confirmed state and
  the reason is shown separately in an error style until a recheck or a full refresh succeeds.
- **Menu-bar quit (#121).** A status item with 打开主控制台 / 设置… / 退出 AICC. The only quit
  entry used to be inside Settings → 高级与诊断, unreachable once the windows were closed.

### Install and upgrade

- **Both `/Applications` and `~/Applications` are supported.** The earlier note that
  `/Applications` hangs at `_dyld_start` on this machine turned out to be a misdiagnosis:
  a non-notarized bundle carrying `com.apple.quarantine` is held **before dyld** by Gatekeeper
  while `CoreServicesUIAgent` shows an alert that only offers 完成 / 移到废纸篓. An `.accessory`
  app with no Dock icon simply looks like it did nothing. Matrix in
  `docs/INSTALL_PATH_ROOT_CAUSE.md`.
- **The DMG now ships `安装说明.txt`** with the approval step, the quit entry and the rollback.
- **Widget self-repair works from `~/Applications`.** The translocated launch only looked in
  `/Applications`; it now tries `/Applications` then `~/Applications` and distinguishes
  "no installed copy" from "could not clear quarantine".
- **Database 26 → 29 adds only three rotation tables** (`workbuddy_rotation_plan`,
  `workbuddy_rotation_run`, `workbuddy_rotation_step`); `accounts` and `qoder_accounts` are
  unchanged. The 2.13.0 worker reads a v29 database fine, but rollback still means restoring
  the database backup together with the old `.app`.
