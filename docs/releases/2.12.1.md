# AICC v2.12.1 / macOS Build 23

## 中文

- **修复墨水屏「配对了却不显示数据」**：发现流程探测服务器时不带凭据，会把候选标记成「需要配对」；随后带 token 复探虽然已经取到快照，却没有清掉这个标记，于是 App 直接丢弃刚拿到的数据并要求重新配对。IP 变化（DHCP 续租）、路由器重启、单次轮询超时都会走到这条路径，表现就是面板一直空着、设置里一直提示输入配对码。现在复探成功会清除标记。
- **修复刷新彻底停摆**：刷新中的互斥标志只在成功路径复位，任何意外异常都会让它一直为真，之后再也不刷新，只能重启 App。改为在 `finally` 复位。
- **修复刚启动时的「Magpie 暂无额度」**：桥接要等第一次读 Magpie 回来才有数据，落在这个窗口里的刷新会把空快照画到面板上，然后干等一整个刷新周期（默认 5 分钟）。现在空结果 15 秒后重试，最多 4 次。
- **测试**：新增 `reProbeWithStoredCredentialClearsPairingFlag`，用同一台假服务器的「需要配对」模式复现上面第一条（无凭据探测 → 带凭据复探 → 断言标记被清除）。
- **发版脚本**：`scripts/release-publish.sh` 的仓库地址与清单里的两个链接不再写死，改从 `remote.origin.url` 解析，fork 不会把包传到上游。
- **文档**：两份 README 的版本从 2.11.0 / Build 16 更正为当前版本。
- **macOS 端本轮没有功能改动**，只为版本号重建了 DMG；已经装 2.12.0 的 Mac 不必重装。

## English

- **The e-ink panel no longer demands pairing while its credential is valid.** Discovery probes a server without a credential, which marks it pairing-required. The follow-up probe with the stored token did fetch the snapshot but never cleared that mark, so the app threw the data away and opened the pairing dialog. Every fallback to discovery took that path — a DHCP lease change, a router reboot, one timed-out poll — and left the panel blank. A successful probe now clears it.
- **Refresh can no longer wedge.** The in-flight flag was cleared on the happy path only, so any unexpected error blocked every later refresh until the app was restarted. It is now cleared in a `finally`.
- **No more "Magpie 暂无额度" right after start.** The bridge has nothing to answer with until its first Magpie read lands; a refresh landing in that window drew an empty panel and then waited a whole interval (5 minutes by default). An empty answer now retries after 15 seconds, four times.
- **Test:** `reProbeWithStoredCredentialClearsPairingFlag` drives the same candidate through an unpaired and then a paired probe against the fake server's pairing mode.
- **Release script:** the repository and the two manifest URLs now come from `remote.origin.url` instead of being written out, so a fork publishes to itself.
- **Docs:** both READMEs named 2.11.0 / Build 16 and now match the release.
- **No macOS behaviour changed this round**; the DMG is rebuilt for the version bump, so an installed 2.12.0 does not need replacing.

## 安装 / Installation

- macOS：下载 `AICC-2.12.1.dmg`，核对 SHA256；退出 AICC 后将应用拖入 `/Applications` 替换旧版。ad-hoc 签名每次构建 cdhash 都变，桌面小组件需要重新添加一次（额度小组件的配置不受影响）。
- macOS: Download the DMG, verify its SHA256, quit AICC, replace the app in `/Applications`. An ad-hoc signature changes cdhash on every build, so re-add the widgets once; their settings are kept.
- 墨水屏：`versionCode 13 / 1.2.7-pencil-home`。本轮修的是 APK，需要用带 JDK 与 Android SDK 的机器重新构建（`./gradlew -p android/poke-dashboard assembleRelease`）并签名后安装；Mac 端升级无需重新配对。
- E-ink: `versionCode 13 / 1.2.7-pencil-home`. The fix is in the APK, so rebuild it where a JDK and the Android SDK are available (`./gradlew -p android/poke-dashboard assembleRelease`) and sign it before installing. Upgrading the Mac side does not need re-pairing.
- 沿用 ad-hoc 签名，未经 Apple 公证；需要 macOS 14+、Apple Silicon 和 Python 3.10+。DMG 内置完整服务器源码，不含 Python 解释器。
- Uses ad-hoc signing without Apple notarization. Requires macOS 14+, Apple Silicon and Python 3.10+; the server source is bundled, Python itself is not.
