# AICC v2.14.1 / macOS Build 27

两个功能 Bug 的修复版本。界面、存储结构、RPC 与授权策略均未改动。

## 中文

### 自动轮换不再"永远读不到空闲"

- 夜间轮换判断「你是否在用这台机器」时，只查 `ioreg -c IOHIDSystem -d 1`。
  在 macOS 26/27 上这条查询只回 `Root`：`IOHIDSystem` 不再作为 IOService 暴露，
  `HIDIdleTime` 一条都没有。于是每一轮都判「读不到空闲」，按设计保守推迟，
  到窗口尾部就记成 `skipped` —— 定时轮换永远不会开始（手动切换不受影响，所以看起来"手动能切"）。
- 现在两段式读取：先窄查询，拿不到再 `ioreg -l`（本机 0.16s）。两段都失败仍然返回
  「不知道」，**不会**据此认定你不在用，也不改 120 秒阈值与 60 秒心跳。
- 顺带把 `ioreg` 换成绝对路径 `/usr/sbin/ioreg`：GUI 进程的 `PATH` 不保证带 `/usr/sbin`。

### 借用授权不再"重新授权了还显示已过期"

- 一个账号同时有 Magpie 借用授权和自有授权时，界面的授权状态读的是账号镜像列。
  镜像里的 `token_expires_at` 是**导入那一刻的快照**；Magpie 自己换过令牌之后，
  AICC 里那份快照不会更新，界面就把一份可用授权一直显示成「已过期」。
- 现在 `sync_mirror` 选中 Magpie 授权时会现读 `plugin-auth.json` 的 `expires`：
  只更新时间，不动令牌、不改首选来源、不改授权优先级、不影响 Broker 的读取。
  文件读不到就保留原值 —— 宁可用旧快照，也不把「不知道」写成「已过期」。
- 刷新只更新到期时间，不会把授权标成 expired、不写 `last_error`、不要求重新登录。

### 测试

- 新增 8 个空闲探测用例（正常 / 0 秒 / 超过阈值 / 属性缺失 / 格式错误 / 窄查询失败回落 /
  两段都失败），加一个 `#[ignore]` 的真机只读检查（`cargo test -- --ignored real_ioreg`）。
- 新增 4 个镜像用例（文件里有新到期时间 / 文件读不到保留旧值 / own 行不被写 / 过期镜像刷新不要求重新登录）。
- 修掉两处**定时炸弹夹具**：`handlers` 与 `rpc_stdio` 里写死的 `expires` 是
  2026-11-22T13:42:14Z，到点后导入会被判 `token_expired`，整组用例变红（main 上已经会红）。

## English

### Scheduled rotation no longer reports "idle state unreadable"

- The rotation guard reads HID idle time with `ioreg -c IOHIDSystem -d 1`. On macOS 26/27 that
  query returns only `Root` — `IOHIDSystem` is no longer exposed as an IOService — so every tick
  concluded "cannot tell whether you are away", deferred by design, and eventually recorded the
  night as `skipped`. Scheduled rotation could never start; manual switching was unaffected.
- The probe is now two-step: the narrow query first, then a full `ioreg -l` (0.16 s here). If both
  fail it still returns "unknown" rather than assuming you are away; the 120-second threshold and
  the 60-second heartbeat are unchanged. `ioreg` is addressed by absolute path.

### Borrowed authorisations stop showing "expired" after re-authorising

- When an account has both a Magpie link and its own login, the UI reads the account mirror, whose
  `token_expires_at` was a snapshot taken at import time. Once Magpie rotated its token that
  snapshot went stale and a perfectly usable authorisation was displayed as expired.
- `sync_mirror` now reads `expires` from `plugin-auth.json` when the Magpie row is selected: expiry
  only — no token copied, preferred source unchanged, broker untouched. If the file cannot be read
  the old value is kept.

### Tests

- Eight idle-probe cases plus an `#[ignore]`d real-machine check; four mirror cases; and the two
  date-bound fixtures that had already started failing on main are now far-future.
