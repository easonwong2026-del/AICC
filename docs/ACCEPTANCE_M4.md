## 3. 未验证清单（必须如实出现在任何对外说明里）

1. **Qoder 浏览器授权的真实换票**：设备码流程、`userinfo` 实际字段、
   `token_expires_at` 形态，都没有真实响应。本地状态机有 11 项单测，但那不等于服务端已验证。
2. **PAT 的 `userinfo` 权限范围**：只知道官方文档说 PAT 可用于 CLI；它是否被
   `/sash/...` 接受未测。
3. **Qoder CN Credits 查询 / 领取**：协议来自社区参考实现，AICC 侧零成功响应。
4. **`Cosy-Machine*` 风控头**：参考实现从桌面客户端取这些值；AICC **不伪造**。
   若服务端因此拒绝，结论应写成"缺客户端风控头"，不是"接口不存在"。
5. **Qoder International 的 Credits 能力**：`blocked`，零请求，界面不显示领取按钮。
6. **Qoder CN 客户端 Profile 的真实识别**：本机未安装 CN 客户端，仍沿用 #70 的结论。

## 4. 数据库迁移记录

| 版本 | 内容 | 幂等 | 旧库验证 |
| --- | --- | --- | --- |
| v16 | `qoder_accounts.auth_epoch`；重建 `qoder_authorizations` 以接受 `own_pat` | 是（Rust 步骤，先检测） | `v15_upgrade_keeps_qoder_authorizations_and_accepts_pat` |
| v17 | `qoder_accounts.credits_auto_enabled` + `qoder_credit_runs` | 是（先检测列） | 同上（同一条用例覆盖到最新版本） |

回滚策略：

- **数据**：两张表都是"只追加列 / 只建新表"，旧二进制读到多出来的列会忽略；
  降级不需要脚本。`qoder_authorizations` 的重建保留了全部列与原值，回滚只需把
  `CHECK` 里多出来的 `own_pat` 去掉（若库里已有 `own_pat` 行，需先删或改 `source`）。
- **验证方式**：`legacy_db(15)` 造真实旧库 → `Db::open` 迁到最新 → 断言账号、
  授权、指纹、到期时间一字不差，且新来源可写、表外来源仍被拒。
- **不重建、不清空**：迁移过程没有任何 `DELETE`；唯一的 `DROP TABLE` 是
  重建 `qoder_authorizations` 前的旧表，数据在同一个事务内已搬到新表。

## 6. 怎么验收（不需要交出任何令牌）

### 6.1 应用启动

装 `dist/mac/AICC.app` 到 `~/Applications`（这台机器 `/Applications` 有环境问题，
装那里会卡在 `_dyld_start`），打开「AI 账号」。

### 6.2 Qoder 授权（#73）

1. 选 Qoder CN → 「浏览器授权」→ 浏览器完成登录 → 账号出现在 CN 分区；
2. 换 Qoder International 重复一次 → 两行账号、两套来源，互不覆盖；
3. 再对一个账号点「PAT」→ 粘贴账户页生成的令牌 → 提示"已保存并验证身份"；
4. 「检测 PAT」应回答身份是否仍有效；「移除 PAT」后浏览器授权那行还在。

判据：令牌不出现在界面、数据库、日志里；`qoder_accounts` 里只多出元数据。

### 6.3 Qoder Credits（#75）

1. 额度页 Qoder 卡片 → 「检查」：返回可领 / 已领 / 无活动 / 未支持之一；
2. 若可领 → 「领取今日」→ 结论必须带"服务端已确认"；
3. 签到任务页 Qoder 段 → 打开「自动领取」→ 次日检查 `trigger=auto` 的记录；
4. International 卡片应显示"暂未支持"，且**没有**领取按钮。

出现 `unauthorized` / `error` 时，把**脱敏后**的文案记下来即可，不需要贴令牌。

### 6.4 WorkBuddy 侧（#76 回归）

1. 签到页顶部概览：完成 / 待完成 / 需重新授权 / 自动开启 / 最近失败；
2. 签到、成长、旅行各自跑一次手动动作，概览数字应跟着变；
3. WorkBuddy AI 账号不应出现在签到的"待完成"里（它没有国内版协议）。
